# 기술 스택 슬라이드 · 발표 대본 (핵심 기능 연계)

발표 시간에 맞춰 문단을 줄이거나, 괄호 안은 필요할 때만 보강하면 됩니다.  
슬라이드의 백엔드 항목 표기는 **QueryDSL**이 정확합니다. (오타로 **Query DLS**가 보이면 수정 권장.)

---

## 오프닝 (5~15초)

> “기술 스택은 **우리가 만든 핵심 기능을 어떻게 지원하는지** 위주로 말씀드리겠습니다. 전체 구조는 프론트는 React 중심, API와 실시간은 Spring Boot, 데이터는 MySQL을 쓰고, 방송만 별도 Node 기반 파이프라인으로 두었습니다.”

---

## 01. 조건 별 실시간 매칭 · 전용 채팅

> “매칭 조건을 맞춰 팀원을 모집하고, 매칭이 잡히면 **전용 채팅**으로 바로 이어지는 흐름이 필요했습니다.  
> 그래서 HTTP만으로는 부족한 **실시간 구간**에는 **Spring WebSocket** 위에 **STOMP**를 올리고, 브라우저 호환을 위해 **SockJS**로 접속했습니다.  
> 매칭·방 생성 같은 **비즈니스 처리와 상태**는 **Spring Boot**와 **Spring Data JPA**로 REST 형태로 두고, 채팅·알림처럼 **밀어내기가 필요한 부분**만 WebSocket으로 나눴습니다.”

(짧게 할 때)  
> “실시간 채팅과 동기화는 **WebSocket + STOMP + SockJS**, 매칭 로직과 API는 **Spring Boot + JPA**로 분담했습니다.”

---

## 02. AI 전적 분석

> “전적 데이터를 단순 숫자로 보여주는 데 그치지 않고, **해석과 개선 방향**까지 주려면 서버에서 데이터를 정리한 뒤 **AI 쪽 API**와 연동하는 구조가 필요합니다.  
> 백엔드는 **Java / Spring Boot**로 전적·요약 데이터를 조회·가공하고, 분석 요청은 프로젝트에 맞는 **외부 LLM 클라이언트**로 보내는 식으로 역할을 나눴습니다.  
> 조회가 복잡해지는 부분은 **QueryDSL**로 동적 조건을 정리해 유지보수하기 쉽게 했습니다.”

(짧게 할 때)  
> “전적은 **Spring Boot + JPA·QueryDSL**로 모으고, **AI 분석은 외부 API 연동**으로 처리했습니다.”

---

## 03. 라이브 스트리밍 서비스

> “매칭 대기 중에도 방송을 올릴 수 있게 하려면, 게임 캡처는 보통 **OBS → RTMP**로 나가고, 웹에서는 **HLS**로 재생하는 조합이 현실적입니다.  
> 그래서 **Node Media Server**로 RTMP를 받고 **FFmpeg**로 HLS로 바꾼 뒤, 브라우저에서는 **hls.js**로 재생합니다.  
> 이 파이프라인은 메인 API 서버와 역할이 달라서 **별도 프로세스**로 두었고, 앱 본체는 여전히 **Spring Boot + React**입니다.”

(짧게 할 때)  
> “방송은 **Node Media Server + FFmpeg + hls.js**로 RTMP를 HLS로 바꿔 웹에서 재생합니다.”

---

## 04. 계정 연동 및 통합 게임 프로필

> “스팀·라이엇처럼 계정이 흩어져 있으면, 로그인과 신뢰도 측면에서 **통합 프로필**이 필요합니다.  
> 웹 서비스 입장에서는 **Spring Security**와 **OAuth2**로 구글·카카오·네이버 같은 **소셜 로그인**을 붙이고, 전화 인증 등은 **Firebase** 클라이언트 SDK로 보완합니다. 서버 쪽 검증·연동에는 **Firebase Admin SDK**를 사용합니다.  
> 팀·전적 같은 데이터는 **MySQL**에 두고, 외부 게임 플랫폼 연동은 REST로 단계적으로 묶었습니다.”

(짧게 할 때)  
> “로그인·보안은 **Spring Security, OAuth2, Firebase**, 프로필·전적 데이터는 **MySQL**에 둡니다.”

---

## 마무리 (5~10초, 선택)

> “정리하면, **실시간 채팅·동기화**는 WebSocket 쪽, **방송**은 RTMP–HLS 파이프라인, **계정**은 Security·OAuth·Firebase, **화면**은 React·Vite·React Router로 역할을 나눴고, 그 중심 API는 Spring Boot입니다.”

---

## 짧은 버전 전체 대본 (한 번에 읽기)

아래는 위에 흩어 둔 **「짧게 할 때」** 문장과 초간단 오프닝·마무리만 모은 연속 대본입니다.

> “기술 스택은 **핵심 기능별로** 어떤 기술을 썼는지만 짧게 말씀드리겠습니다. 프론트 서버는 **React**, 백엔드 서버는 **Spring Boot**, 데이터는 **MySQL**, 스트리밍은 **Node Media Server** 로 두었습니다.”
>
> “**실시간 매칭과 전용 채팅**은 **WebSocket + STOMP + SockJS**로, 매칭 로직과 API는 **Spring Boot + JPA**로 나눴습니다.”
>
> “**AI 전적 분석**은 전적을 **Spring Boot + JPA·QueryDSL**로 모은 뒤, **AI 분석은 외부 API 연동**으로 처리했습니다.”
>
> “**라이브 스트리밍**은 **Node Media Server + FFmpeg + hls.js**로 RTMP를 HLS로 바꿔 웹에서 재생합니다.”
>
> “**계정 연동·통합 프로필**은 로그인·보안을 **Spring Security, OAuth2, Firebase**로, 데이터는 **MySQL**에 뒀습니다.”
>
> “정리하면, 실시간은 WebSocket, 스트리밍은 RTMP–HLS, 계정은 Security·OAuth·Firebase, 화면은 **React·Vite·React Router**, 중심 API는 **Spring Boot**입니다.”
