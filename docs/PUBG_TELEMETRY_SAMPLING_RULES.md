# PUBG 텔레메트리 샘플링 규칙 (AI 분석용)

> AI 분석 엔진(LLM)에 데이터를 넣을 때는 **"데이터의 양"보다 "데이터의 밀도(의미)"**가 중요합니다.
> 전략적 데이터 다이어트를 통해 최적의 피드백 품질을 확보합니다.

---

## 1. 원칙

| 구분 | 설명 |
|------|------|
| **목표** | AI가 상황을 완벽히 이해할 수 있는 최소·최적 데이터 |
| **핵심** | 평소엔 아주 드물게(30초), 교전 시엔 아주 촘촘하게(1초) |
| **형식** | 좌표 나열 금지 → 의미 부여된 텍스트 요약으로 가공 |

---

## 2. 상황별 샘플링 밀도

### 2.1 밀도 매트릭스

| 상황 | 추천 기록 밀도 | AI에게 주는 정보 |
|------|----------------|------------------|
| **단순 이동/파밍** | 20~30초당 1개 | "이 구역에서 파밍 후 차량으로 이동함" (전체 운영 파악) |
| **교전 발생 전(진입)** | 5초당 1개 | "적 근처 건물로 붙는 중" (포지셔닝 분석) |
| **교전 중(피격/타격)** | 1초당 1개 (전부) | "엄폐물 없이 개활지에서 맞음" (피드백의 핵심) |

### 2.2 이벤트 타입별 규칙

| 이벤트 타입 | 샘플링 | 비고 |
|-------------|--------|------|
| **LogPlayerPosition** | 가변적 (아래 3.1 참고) | 1~2초마다 발생 → 반드시 샘플링 |
| **LogPlayerTakeDamage** | 전체 수집 | 교전 핵심, 1초 단위 |
| **LogPlayerAttack** | 전체 수집 | 교전 핵심 |
| **LogPlayerMakeGroggy** | 전체 수집 | 교전 핵심 |
| **LogPlayerKill, LogPlayerKillV2** | 전체 수집 | 교전 핵심 |
| **LogHeal** | 전체 수집 | 교전·생존 분석 |
| **LogItemPickup, LogItemDrop** | 샘플링 (30초당 1개) | 파밍 구간에서만 |
| **LogVehicleRide, LogVehicleLeave** | 전체 수집 | 이동 구간 구분용, 건수 적음 |
| **LogMatchStart, LogMatchEnd** | 전체 수집 | 각 1개 |
| **LogGameStatePeriodic** | 60초당 1개 | 자기장 페이즈 변화만 |

## 3. 가변적 샘플링 알고리즘

### 3.1 LogPlayerPosition 샘플링 로직

```
입력: 이벤트 스트림 (시간순)
출력: 샘플링된 위치 이벤트 목록

상태:
  - lastSampleTime: 마지막 샘플링 시각
  - combatWindowStart: 교전 구간 시작 시각 (null = 비교전)
  - combatWindowEnd: 교전 구간 종료 시각

규칙:
  1. 교전 이벤트(LogPlayerTakeDamage, LogPlayerAttack, LogPlayerMakeGroggy, LogPlayerKill) 발생 시:
     - combatWindowStart = 해당 이벤트 시각 - 10초  (진입 구간 포함)
     - combatWindowEnd = 해당 이벤트 시각 + 5초 (사후 분석용)

  2. 위치 이벤트(LogPlayerPosition) 처리 시:
     - 현재 시각이 [combatWindowStart, combatWindowEnd] 안에 있으면:
       → 1초당 1개 수집 (같은 초 내 중복 제거)
     - combatWindowEnd 직전 30초 구간(진입 직전):
       → 5초당 1개 수집
     - 그 외 (단순 이동/파밍):
       → 20~30초당 1개 수집
```

### 3.2 교전 구간 정의

| 구간 | 시간 범위 | 샘플링 밀도 |
|------|-----------|-------------|
| **진입** | 교전 이벤트 -30초 ~ -10초 | 5초당 1개 |
| **교전 중** | 교전 이벤트 -10초 ~ +5초 | 1초당 1개 (전부) |
| **이후** | 교전 이벤트 +5초 ~ 다음 교전 또는 60초 | 20초당 1개 |

## 4. 프롬프트용 텍스트 가공

### 4.1 나쁜 예 (데이터 나열)

```
14:05:01 - x: 1542, y: 3421
14:05:02 - x: 1545, y: 3425
14:05:03 - x: 1548, y: 3428
...
```

### 4.2 좋은 예 (의미 부여)

```
[운영] 14:00~14:04: 강남 지역에서 파밍 완료 후 2단계 자기장 진입 시작.

[위험] 14:05:00: 적 Labet-_-와 150m 거리에서 교전 발생.
  - 나의 위치: 능선 아래
  - 적의 위치: 능선 위 바위

[결과] 14:05:10: 헤드샷 판정으로 사망.
```

### 4.3 가공 템플릿

| 구간 | 접두사 | 예시 |
|------|--------|------|
| 단순 이동/파밍 | `[운영]` | `[운영] 14:00~14:04: 강남 지역 파밍 후 차량 탑승, 2단계 자기장 진입` |
| 교전 진입 | `[위험]` | `[위험] 14:05:00: 적 PlayerX와 150m, 건물 진입 중` |
| 교전 중 | `[교전]` | `[교전] 14:05:08: 피격 45 데미지, 무기: M416, 거리 80m, 상대: Labet-_-` |
| 사망/킬 | `[결과]` | `[결과] 14:05:10: 헤드샷으로 사망, 킬러: Labet-_-` |
| 회복 | `[회복]` | `[회복] 14:03:22: 구급상자 사용, 75→100` |

### 4.4 수직성(verticality) 태그

`location_z` 값을 활용해 수직적 위치를 LLM이 파악할 수 있도록 태그를 부여합니다.

**주의**: 지형마다 바닥 Z가 다르므로 전역 고정 구간(z < 500 등)은 부적절. [PUBG_MAP_REGION_MAPPING.md §3.3](PUBG_MAP_REGION_MAPPING.md#33-z값수직성-분류) 참고. 초기에는 지역명만 사용하고 수직성 태그는 생략 가능.

| 목표 태그 | 예시 |
|-----------|------|
| `[지면]` | 평지, 도로 |
| `[건물 내부]` | 실내 교전 |
| `[건물 옥상]` | 고지대 사격 |
| `[언덕 위]` / `[능선 아래]` | 지형 우위 |

→ 구현 시 지역별 `groundZ` 또는 매치 내 상대 높이 필요. 단순 절대값 구간 분류는 사용 금지.

## 6. 참고: 문제점 정리

| 문제 | 원인 | 대응 |
|------|------|------|
| **토큰 낭비** | 1초 단위 로그 전부 입력 | 가변적 샘플링 |
| **노이즈** | 수만 좌표 중 교전 순간 묻힘 | 교전 구간 밀도 상향 |
| **할루시네이션** | 숫자 과다 → AI 계산 오류 | 의미 텍스트로 가공 |
| **맥락 상실** | 죽기 직전 30초 정보 없음 | 교전 전 5초 밀도 보장 |
