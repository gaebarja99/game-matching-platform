# Valorant 승리기여도 기반 라운드 점수 엔진 계획서

## 1. 목표

- **점수 철학**: 킬 숫자보다 **승리 기여도**를 반영. 단, 결과론이 아닌 **과정 기준**.
- **계산 단위**: 라운드별 점수 → 매치 점수 = 라운드 점수의 **평균**
- **가중치 원칙**:
  - **경제 역전(로드아웃)**: 높은 가중치 (상대가 경제 유리일 때 우리 킬 = 역전 기여)
  - **상황 변화(Situation Impact)**: 킬 전→후 인원수 변화로 킬 가치 평가. **패배 라운드에서도** 3v4→3v3 같은 "열세→동률" 킬은 높은 점수
  - **클러치(역전 승리)**: 결과 기반. 라운드 승리 시에만 +45 보너스

---

## 2. 점수 설계 상세

### 2-1. 라운드 점수 공식

```
라운드_점수 = BASE_SCORE (100)
  + Σ(킬_가중_점수)           // 경제 역전 × 상황 변화 (패배라도 3v4→3v3等高가치 반영)
  + Σ(어시스트_점수)          // KillEvent.assistants 기반, 킬 가치의 40%
  + Σ(데미지_기여_점수)       // 제거된 적에게 가한 데미지 비율 (120피 깎고 킬 못해도 기여 인정)
  + 클러치_보너스             // roundWon && 클러치 조건 (1v2+ 역전 승리)
  - 사망_패널티              // 컨텍스트별 (트레이드 0, 5v5단독 -25, 일반 -20 등)
  + roundWon_보너스          // 승리 시 +15 (클러치와 별도)
  - Afk/Penalized_패널티     // -100
```

### 2-2. 킬 가중 점수 (경제 역전 × 상황 변화)

**설계 철학**: 킬 가치는 **라운드 승패와 무관**하게 "그 순간 얼마나 중요한 플레이였는지"로 평가. 3v4→3v3 킬은 패배해도 동률로 맞춘 기여가 인정됨.

| 요소 | 설명 | 가중치 |
|------|------|--------|
| **기본 킬값** | 킬 1개당 기본 점수 | +15 |
| **경제 역전 지수** | `max(their / max(our, ECONOMY_FLOOR), 0.8)` | ×0.8 ~ ×1.5 |
| **상황 변화 배율 (Situation Impact)** | 킬 전→후 인원수 변화 | 아래 표 |

**경제 역전 지수 (Economic Reversal)**:
- `max(their / max(our, ECONOMY_FLOOR), 0.8)` — 상대가 에코·우리가 풀바이일 때도 최소 ×0.8 보장
- ECONOMY_FLOOR(1500): 에코 라운드 기본 구매(권총+스킬) 고려, 극단적 배율 변동 방지

**상황 변화 배율 (패배 라운드에서도 적용)**:

| 킬 전 | 킬 후 | 해석 | 배율 |
|-------|-------|------|------|
| 3v4 | 3v3 | 열세→동률 | ×1.4 |
| 2v3 | 2v2 | 열세→동률 | ×1.4 |
| 1v2 | 1v1 | 열세→동률 | ×1.4 |
| 1v3 | 1v2 | 열세→여전히 열세 | ×1.1 |
| 2v2 | 2v1 | 동률→우세 | ×1.2 |
| 4v1 | 4v0 | 클린업(스탯 세탁) | ×0.75 |
| 5v5 | 5v4 | 첫 킬(FB, 라운드 승률 ~70% 기여) | ×1.35 |

### 2-3. 어시스트 점수

**데이터 소스**: `KillEvent.assistants` (assistant_puuid 리스트). 해당 킬의 최종 킬러가 받는 킬 점수와 **동일 상황**으로 어시스트 참여자에게 배분.

**어시스트 점수 (데미지 비례 보상)**:

| 데미지 | 데미지 배율 | 어시스트 점수 (킬 15점 기준) |
|--------|-------------|------------------------------|
| 0 (스킬: 연막·섬광·힐·스캔 등) | **1.0** (전액 인정) | 6점 |
| 40 | 0.4 | 2.4점 |
| 60 | 0.6 | 3.6점 |
| 100 | 1.0 | 6점 |
| 140 | 1.2 (상한) | 7.2점 |

**공식**: `어시스트_점수 = 킬_가치 × 0.4 × 데미지_배율`

- **데미지 배율** = `(내_데미지 > 0) ? min(1.2, 내_데미지/100) : 1.0`
  - 데미지 0 → **1.0** (스킬 어시스트 전액 인정)
  - 데미지 100 이상 → 1.0, 140 이상 → 1.2 상한

**다중 어시스트**: 각 어시스트자는 위 공식으로 **개별 계산** (데미지에 따라 차등 적용)

→ 연막·섬광·다트·힐 등 논킬 기여도 전액 인정. 무기 데미지는 기여도에 비례하여 보상.

### 2-4. 데미지 기여 점수

**설계 철학**: 상대에게 준 데미지는 승리 기여도에 직접 반영. 120데미지로 몸을 1대만 맞추면 킬할 수 있게 한 경우, 40데미지로 풀피 적을 잡은 경우와 구분.

**데이터 소스**: `RoundPlayerStat.damage_events` (attacker=playerPuuid, receiver, damage). 킬 이벤트와 교차하여 **제거된 적**(victim)에게 누가 얼마나 데미지를 줬는지 집계.

| 항목 | 설명 | 적용 |
|------|------|------|
| **킬 데미지 비율** | 킬러 본인이 해당 적에게 가한 데미지로 킬 가치 보정 | `킬_가치 × max(0.6, min(1.0, 내_데미지/100))` |
| **제거 기여 데미지** | 킬 없이 제거된 적에게 가한 데미지 | `(데미지/100) × DAMAGE_SCORE_PER_100` (킬러·**어시스트자는 제외**) |

**킬 데미지 비율 (풀피 vs 클린업)**:
- 풀피(100+) 킬: 내 데미지 100 이상 → 1.0x (전부 인정)
- 40 HP 적 클린업: 내 데미지 40 → 0.6x (킬이면 최소 60% 인정, 클린업도 적정 평가)
- 20 데미지 스틸: 최소 0.6x (최소 가치 보장)

**제거 기여 데미지 (상호 배타적 적용)**:
- **어시스트 판정을 받은 플레이어**는 해당 victim에 대해 **어시스트 점수만** 받고, 데미지 기여 점수는 지급하지 않음 (이중 지급·점수 역전 방지)
- 어시스트 없이 데미지만 준 플레이어(예: 40데미지) → `(데미지/100) × DAMAGE_SCORE_PER_100` 보정 지급
- 140데미지 + 아군 막타: 어시스트 ~7.2점만 (데미지 비례 1.2, 데미지 점수 추가 X) → 킬러(9점)보다 높아지는 역전 방지
- `damage_events`에서 receiver가 킬당한 적인지 킬 이벤트와 매칭

→ 킬/어시스트에 못 들어간 데미지 기여도만 보정으로 반영.

### 2-5. 클러치 보너스  

**조건 (좁은 정의)**: `roundWon == true` 이고, **나 혼자 살아남은 상태(1vN)에서 상대가 2명 이상 살아있을 때** 승리한 경우.

| 조건 | 설명 |
|------|------|
| 우리팀 생존 1명 | 본인만 살아남음 |
| 상대팀 생존 ≥ 2명 | 1v2, 1v3, 1v4, 1v5 |
| 라운드 승리 | 최종 우리팀 승리 |

**보너스**: +45

→ 2v3, 4v5 같은 경우는 클러치 아님. **1v2+ 역전 승리**만 클러치.

### 2-6. 시나리오별 예시

| 상황 | 경제 | 상황 변화 | 클러치 | 예상 점수 |
|------|------|-----------|--------|-----------|
| 1v3에서 1킬 후 사망 | 역전일 수 있음 | 1v3→1v2 (×1.1) | 없음 | 100 + 16~17 (폭등 없음) |
| 3v4에서 1킬 후 패배 | 역전 | 3v4→3v3 (×1.4) | 없음 | 100 + 21~22 (패배해도 동률 맞춘 기여 인정) |
| 1v3에서 3킬 후 승리 | 역전 | 1v3→1v2→1v1→1v0 | O | 100 + 킬가중 + 45 + 15 = 175+ |
| 4v1 클린업 1킬, 승리 | 유리 | 4v1→4v0 (×0.75) | 없음 | 100 + 11 + 15 = 126 |
| 경제 역전 킬 2개, 승리 | 역전 | 비슷 | 없음 | 100 + 35 + 15 = 150 |

## 3. 데이터 구조

### 3-1. KillContext (신규)

킬 하나당 컨텍스트. 라운드 점수 계산 시 사용.

```java
// 패키지: com.gamematcher.dto.ai.evaluation
public record KillContext(
    String killerPuuid,      // 킬한 플레이어
    String victimPuuid,
    int ourAliveAtKill,      // 킬 직전 우리팀 생존 수
    int theirAliveAtKill,    // 킬 직전 상대팀 생존 수
    int ourTeamLoadout,      // 우리팀 라운드 로드아웃 합
    int theirTeamLoadout,    // 상대팀 라운드 로드아웃 합
    int killTimeInRound     // 라운드 내 킬 시각(ms)
)
```

### 3-2. AssistContext (신규)

어시스트 1건당. 해당 킬의 컨텍스트. 데미지 비례 점수는 `damageToEliminated`(victim→데미지)로 조회.

```java
// 패키지: com.gamematcher.dto.ai.evaluation
public record AssistContext(
    KillContext killContext   // 어시스트한 킬의 컨텍스트 (킬 가치·victimPuuid 포함)
)
```

→ `killContext.victimPuuid`로 `damageToEliminated` 조회. 없으면 0 (스킬 어시스트, 배율 1.0)

### 3-3. RoundScoreInput (신규)

플레이어 1명의 라운드 1개 점수 계산 입력.

```java
// 패키지: com.gamematcher.dto.ai.evaluation
public record RoundScoreInput(
    ValorantRoundStatsDTO playerRoundStats,  // 기존
    List<KillContext> myKillsInRound,       // 이 플레이어가 한 킬들의 컨텍스트
    List<AssistContext> myAssistsInRound,   // 이 플레이어가 어시스트한 킬들
    Map<String, Integer> damageToEliminated,// victimPuuid → 이 플레이어가 가한 데미지 (제거된 적만)
    Map<String, Integer> myDamagePerKill,    // 내가 킬한 victimPuuid → 내 데미지 (킬 데미지 비율용)
    int ourTeamLoadout,                      // 우리팀 로드아웃 합
    int theirTeamLoadout                     // 상대팀 로드아웃 합
)
```

### 3-4. 기존 DTO 활용

| DTO | 역할 |
|-----|------|
| ValorantRoundStatsDTO | 플레이어 라운드 스탯 (kills, damage, roundWon, loadoutValue, FirstKill 등) |
| ValorantPlayerMatchStatsDTO | 매치×플레이어 (matchStats + roundStats 리스트) |

## 4. 데이터 소스 및 추출 로직

### 4-1. 킬 이벤트 소스

| 소스 | 구조 |
|------|------|
| ValorantMatchDetailDto.kills | `List<KillEvent>` (round, kill_time_in_round, killer_puuid, victim_puuid) |
| Round.playerStats | player_team, economy.loadout_value |
| Round.winningTeam | roundWon 판별 |

### 4-2. 킬 컨텍스트 추출 알고리즘

```
1. 해당 라운드 킬들을 kill_time_in_round 오름차순 정렬
2. 팀별 초기 생존 = 5
3. puuid → team 매핑 생성 (playerStats 또는 all_players)
4. 각 킬마다:
   a. 킬 직전 ourAlive, theirAlive 사용
   b. victim 팀의 alive -= 1
   c. ourAlive, theirAlive에 min(값, 5) 적용 (세이지 부활 시 상한 보장)
   d. KillContext(killer, victim, ourAlive, theirAlive, ourLoadout, theirLoadout, time) 생성
   e. killer 팀의 ourAlive, victim 팀의 theirAlive로 설정 (킬 직후 아님, 직전!)
```

**주의**: 킬 "직전" 생존 수를 사용하므로, 킬 처리 전 상태를 저장한 뒤 victim 팀 생존을 감소시킨다.

**세이지 부활(Sage Resurrection)**: API에 부활 시점·대상 이벤트가 없음. 구현 시 생존 수 상한 `min(alive, 5)` 적용하여 부활로 인한 alive 초과 방지. 별도 부활 보정 로직은 두지 않음.

### 4-3. 클러치 판별

**조건 (좁은 정의)**: **나 혼자 살아남은 상태(1vN)에서 상대가 2명 이상일 때** 최종 승리.

```
클러치 = roundWon && (
  라운드 중 어느 시점이든 (ourAlive == 1 && theirAlive >= 2) 인 구간이 있었음
)
```

→ 2v3, 4v5 등은 클러치 아님. **1v2+ 역전 승리**만 클러치.

## 5. 구현 구성 요소

### 5-1. KillContextExtractor (신규)

**패키지**: `com.gamematcher.service.ai.score`

**역할**: 라운드별 킬 이벤트 + 플레이어 스탯 → `List<KillContext>` (플레이어별 그룹핑 가능하도록)

**입력**:
- `List<KillEvent>` (해당 라운드)
- `List<RoundPlayerStat>` 또는 `ValorantRoundStatsDTO` 리스트 (puuid→team, loadout 매핑용)
- `int roundIndex`

**출력**:
- `Map<String, List<KillContext>>` (killerPuuid → 킬 컨텍스트 리스트)
- `Map<String, List<AssistContext>>` (assistantPuuid → 어시스트 컨텍스트 리스트)

### 5-2. ValorantRoundScoreEngine (신규)

**패키지**: `com.gamematcher.service.ai.score`

**역할**: 라운드 1개×플레이어 1명의 점수 계산

**메서드**:
- `int calculateRound(RoundScoreInput input)` → 라운드 점수

**내부 로직**:
- 킬 가중 점수 (경제 역전 × 상황 변화 × 킬 데미지 비율)
- 어시스트 점수 (킬_가치 × 0.4 × 데미지_배율, 데미지 0→1.0)
- 데미지 기여 점수 (제거된 적에게 가한 데미지, 어시스트자 제외·보정용)
- 클러치 판별 (1v2+ 역전 승리) 및 보너스
- roundWon 보너스
- 사망 패널티 (컨텍스트별: 트레이드 0, 5v5단독 -25, 일반 -20 등)
- Afk/Penalized 패널티 (-100)

### 5-3. ValorantScoreEngine (기존 확장)

**기존**: `calculate(ValorantMatchStatsDTO stats)` — 매치 집계 스탯 기반 (유지 또는 Fallback)

**신규**: `calculateFromRounds(ValorantPlayerMatchStatsDTO playerMatchStats)` → 라운드 점수 평균

**흐름**:
1. `ValorantPlayerMatchStatsDTO`에서 `roundStats` 추출
2. 각 라운드에 대해 `KillContextExtractor`로 킬 컨텍스트 추출
3. `ValorantRoundScoreEngine.calculateRound()` 호출
4. `roundScores`의 평균 반환 (참가 라운드 0이면 0 또는 100 반환 정책 결정)

### 5-4. ScoreEngineRouter / RuleBasedScoreService

- `ValorantPlayerMatchStatsDTO`를 받을 수 있는 오버로드 추가
- `gameCode == VALORANT`이고 `ValorantPlayerMatchStatsDTO`가 있으면 라운드 기반 계산 우선 사용
- `ValorantMatchStatsDTO`만 있으면 기존 `calculate(ValorantMatchStatsDTO)` 사용 (Fallback)

## 8. 엔티티 vs DTO 데이터 소스

**ValorantMatch (Entity) 경로**:
- `ValorantMatch` → `rounds` (ValorantMatchRound) → `roundPlayers` (ValorantMatchRoundPlayer)
- `ValorantMatch` → `killEvents` (ValorantKillEvent)
- `ValorantMatchRoundPlayer`: playerPuuid, loadoutValue, playerTeam, damage, kills, roundWon 등

**ValorantMatchDetailDto (API) 경로**:
- `Round.playerStats` → RoundPlayerStat (loadout_value, team, kills 등)
- `Match.kills` (round 필터) → KillEvent

**선택**: Entity 기반으로 구현 시 DB에서 조회한 ValorantMatch로부터 KillContext 추출. API DTO 기반이면 ValorantMatchDetailDto에서 추출. **현재 프로젝트는 Entity(ValorantMatch) 저장 후 평가하므로 Entity 기반 추천.**

## 10. 설계 철학: 과정 vs 결과

| 구분 | 적용 대상 | 설명 |
|------|-----------|------|
| **과정 기준** | 킬 가중치 (상황 변화) | 킬 순간의 "상황 변화"로 가치 평가. **패배 라운드에서도** 3v4→3v3 킬은 높은 점수 |
| **결과 기준** | 클러치 보너스, roundWon 보너스 | 라운드 승리 시에만 적용. 역전 승리(클러치)는 결과가 있어야 인정 |

→ 킬 기여는 과정으로, 최종 승리는 결과로 분리하여 둘 다 반영.
